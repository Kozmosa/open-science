总体判断：OpenScience 已形成可辨认的全栈单向架构，核心执行、任务、备份、HTTP client 与 generated schema 具备较高 Depth 和 Leverage；维护成本主要来自少数超宽 transport / domain Interface、迁移与 compatibility 知识、前端页面编排过重，以及 Mock 与正式 contract 的双重表达。当前不适合“按行数大拆包”，适合先修 governance drift 与 contract ownership，再做有限、证据驱动的深化。

值得保留的结构

  • HarnessEngine：多个真实 Adapter 共用一个执行 Seam。
  • TaskDispatcher / BackupService：小 Interface 隐藏高复杂度实现。
  • React Query + feature Adapter + shared HTTP client：server state 与 transport 知识集中。
  • OpenAPI → generated transport → drift gate：schema authority 已有高 Leverage 基础。

主要复杂度来源

  • Domain 14,844 行、API 8,899 行，宽 Interface 集中。
  • Domain router 50 routes；Literature 26；Task 20。
  • 迁移/control/compatibility 代码仍约 12k+ 行。
  • 前端 Tasks/Settings 两个 feature 合计 8,817 物理行。

优先风险

  • Literature transport 未由 Pydantic/generated schema 约束。
  • generated operation metadata 未成为 feature caller Interface。
  • EnvironmentsPage / TasksPage 编排过重。
  • 潜在 import 双向边：domain↔literature、environment↔terminal。

必须由用户复核的 PROJECT_BASIS ↔ 工程事实漂移

1. 产品 root / v1 aliases
Basis 表述为 compatibility aliases；当前架构与代码称产品 aliases 已删除，只保留独立 /v1/models、/v1/messages。删除合规性结论暂停。
2. AgenticResearcher 职责
Basis 定义其为统一 Task CRUD 门面；代码仅 3 文件/170 行 preset 与数据类型，实际 CRUD 位于 Domain Task/Attempt/Worker。该 Module 的合并/删除/迁移建议暂停。
3. Literature transport authority
26 routes 直接 request.json()/dict，无 Pydantic request/response schema；前端使用手写 Literature types。与“OpenAPI 唯一 transport schema authority”存在实质漂移。需决定修实现还是人工修 Basis。
4. non-API → ainrf.api
server.py:23 作为 composition root 动态加载 ainrf.api.app。可能是合理装配例外，也可能违反 literal invariant。需用户明确 composition-root 例外。

维护成本判断

  • 可控：测试有效代码约为后端产品 47.3%，Task/Domain/Auth 的正式 HTTP Interface 测试杠杆较好；generated drift gate 和单向前端依赖降低了跨栈改动风险。
  • 偏高：一个 transport 变更可能同时触达 route、集中 schema、generated artifacts、feature Adapter、Mock 和 page test；Literature 当前缺少这条自动闭环。
  • 结构性成本：migration/control/compatibility 的历史知识虽已有 Locality，但仍渗入 domain、terminal、harness Interface；删除需要 telemetry 与治理决策，不能仅靠静态 caller scan。
  • 低杠杆缺口：client_logs 无直接测试；Literature 26 routes 仅约 3 个 HTTP 测试文件；observability、agentic_researcher、state/workspaces 测试调用少。

统计规则

  • 只统计锁定 SHA 的 tracked snapshot；不扫描 node_modules、cache、dist、runtime data 或 ref-repo 工作树。
  • 分类按路径、生成标记与用途互斥；generated、tests、Mock 不并入手写产品。
  • 前端产品只统计 frontend/src/**/*.{ts,tsx,css}；测试单列 frontend/__tests__。
  • route 来自 generated OpenAPI；WebSocket 因不进入 OpenAPI单独静态计数。
  • caller/test coverage 是 import、HTTP client 和测试文件检索证据，不是动态 coverage 百分比。

已知限制与不确定性

  • 未运行 coverage instrumentation，也未以圈复杂度作为 Module Depth 代理。
  • 静态 import 双向边可能由延迟导入、TYPE_CHECKING 或 composition root 造成；需 AST/运行时 gate 确认。
  • tokei 将 Python docstring 通常计为代码；Markdown 不报告“有效代码”。
  • 压缩 JSON 物理行严重低估信息量，因此 generated 以 schemas/operations 辅助解释。
  • 未操作 production、staging、Docker、浏览器或网络业务接口；结论是代码与长期文档静态审计。
  • 四项治理漂移遵循规则未自行裁决；涉及它们的推荐动作明确暂停或要求用户决策。
